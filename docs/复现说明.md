# 环境与复现说明

本目录为独立交付根目录，全部命令均在本目录执行。文本核验需要 Python 3.10+；完整复现入口面向 Ubuntu 22.04/24.04、Linux x86_64、GNU make。证明工具链固定为 Coq 8.20.1 和 OCaml 4.14.2。首次安装和下载依赖需要联网。

## 1. 查看和核验已有成果

成果、案例规约、SMT/Rocq 分工与 OpenHarmony 对照统一见 [README](../README.md)，具体证明见 [命题证明索引](命题证明索引.md)。执行以下命令只读取文件，不运行 QCP、Coq 或网络：

```bash
python3 -B scripts/reproduce.py check
```

Windows PowerShell 中，使用已安装的 Python 3.10+ 并启用 UTF-8：

```powershell
python -X utf8 -B scripts/reproduce.py check
```

核验内容包括全部交付文件的 SHA-256、133 份证明源码及参考头文件的锁定身份、16 项 `Qed`、172 项原始假设输出及其解析、133 项新编译记录、QCP 目标生成核对、五个函数的 OpenHarmony 对照。返回码为零表示保存的文本证据与当前交付一致。

## 2. 准备运行依赖

Windows 用户进行完整复现时，可在 WSL 的 Ubuntu 终端进入仓库后执行下列 Linux 命令。当前 Windows 路径 `D:\cnm\-` 对应：

```bash
cd /mnt/d/cnm/-
```

若仓库位于其他目录，请替换为实际路径。仓库只锁定 Linux x86_64 的 QCP 工件；下面的完整生成和构建命令需在 Linux 环境中执行。

首次安装请使用有 sudo 权限的普通用户：

```bash
bash scripts/setup-ubuntu.sh
```

该脚本安装基础系统包，在本目录 `.tools/coq/` 中建立固定版本 opam switch，并下载 QCP。安装过程中只需 opam 提供的 Coq 标准库，不需要额外的 Python 包或单独安装 Z3。

单独下载 QCP：

```bash
python3 -B scripts/fetch-qcp.py
```

下载入口绑定作者固定提交中的 `linux-binary/symexec`，并验证 SHA-256：

```text
f7f91a17795714e44652cdac94f4c9df23db5ccc90aec4c31940d483b62d0658
```

下载后路径为 `.tools/qcp/symexec`。只下载运行本项目所需的可执行文件，不下载整个仓库或编辑器扩展。

如果已有固定工件，可将它导入本目录的运行时依赖区并校验：

```bash
python3 -B scripts/fetch-qcp.py --from-file /path/to/symexec
```

也可以在复现命令中直接指定该可执行文件的路径。已有 Coq 环境可以用 `--coq-bin` 指定同时包含 `coqc`、`coqdep`、`ocamlc` 的工具目录。

## 3. 完整复现

使用准备好的默认依赖：

```bash
python3 -B scripts/reproduce.py full --jobs 2
```

指定已有工具链和 QCP：

```bash
python3 -B scripts/reproduce.py full \
  --coq-bin /path/to/opam-switch/bin \
  --qcp-bin /path/to/symexec \
  --jobs 2
```

完整链路依次执行以下操作：

1. 检查锁定源码和证明覆盖，在新目录中复制必要源码。
2. 对三个 C 输入运行固定 QCP，重新生成目标、证明模板和检查接口。
3. 将生成目标与固定目标按 LF 归一后比较，确认目标和接口相同。
4. 恢复交付中完整的作者证明、新增证明及固定共享框架，重新计算依赖。
5. 从零编译 133 个所需模块，检查三个 `goal_check`。
6. 执行 172 项 `Print Assumptions` 查询，定位完整依赖名并核对实际模块成员。
7. 对固定 OpenHarmony 头文件进行离线源码对照，生成汇总和文本证据。

所有命令采用返回码检查，构建失败会返回非零；输出保存在当前批次中。`--jobs 1` 可降低并行构建数量。

## 4. 只复核命题证明

如果只需对固定目标重新检查完整证明，可跳过 QCP 运行：

```bash
python3 -B scripts/reproduce.py build \
  --coq-bin /path/to/opam-switch/bin \
  --jobs 2
```

这一模式同样从纯源码编译 133 个模块并执行完整假设审计，输出中的 `qcp_rerun` 为 `false`。完整模式为 `true`，以区分两种验证范围。

也可以使用 Makefile 的 `check`、`download`、`build`、`full` 入口。例如在默认依赖已准备时执行 `make full JOBS=2`。

## 5. 输出位置与验收

每次构建默认创建 `runs/YYYYMMDDTHHMMSS时区/`。可通过 `--output /path/to/new-directory` 指定新目录，脚本拒绝覆盖已有目录，也拒绝把输出写入源码或已归档证据区。

成功结果应满足：

| 文件或字段 | 预期 |
| --- | --- |
| `summary.json` 的 `status` | `passed` |
| `vc_count` / `reused_proofs` / `new_proofs` / `admitted` | `16 / 7 / 9 / 0` |
| `fresh_compiled_modules` | `133` |
| `shared_strategies` / `assumption_queries` / `module_members` | `35 / 172 / 121` |
| `build.status.json` 的 `exit_code` | `0` |
| `generation.json` | 完整模式下，三个案例目标及检查接口的生成哈希与固定哈希相同 |
| `comparison.json` | `statement_count = 12`，`raw_equal_count = 10` |

`assumptions/` 保存逐项原始输出，`locations/` 保存完整名称定位，`vc-status.md` 提供逐目标表格。`SeparationLogic/` 是本批次实际编译目录，含新生成的 `.vo` 等临时产物。

本次交付中的 [evidence/](../evidence/) 已保存 2026-10-26 完整成功运行的文本结果；原始命令中的 `/home/user/...`、`/tmp/...` 是当时的执行路径，不需要在新机器上重建，复现时使用本机实际工具路径即可。为保持体积和可移植性，归档时只保留文本证据和审计输入；工具链、下载文件及编译产物未随交付保存。

该次完整链路使用已有工具链；`setup-ubuntu.sh` 未在空系统中再次安装验收。没有兼容工具链时可先运行 `check`，但只有新的 `full`/`build` 成功才表示重新执行了对应范围的验证。

## 6. 搬移与重新分发

拷贝整个交付目录即可携带必要源码、证明、参考材料及文本成果。运行时依赖的 opam switch 含安装路径；移动后可重新运行安装入口，或用 `--coq-bin` 指向可用工具链。

需要重新分发精简交付时，保留 README、`src/`、`references/`、`scripts/`、`docs/`、`evidence/`、`licenses/`、Makefile、锁定清单和完整性清单即可。`.tools/` 与 `runs/` 为本地运行产物，不属于交付文件集合。

## 7. 常见问题

| 现象 | 处理办法 |
| --- | --- |
| 找不到 `python3`，或版本低于 3.10 | 检查 `python3 --version`；Windows 使用 `python --version`。需要安装 Python 3.10+ |
| 找不到 `coqc`、`coqdep`、`ocamlc` | 运行环境准备脚本，或通过 `--coq-bin` 指定同时包含这些工具的目录；版本须为 Coq 8.20.1 / OCaml 4.14.2 |
| QCP 文件缺失、哈希不符或无执行权限 | 用 `fetch-qcp.py` 下载固定工件，或以 `--from-file` 导入；不使用作者主分支的其他版本替代 |
| 输出目录已存在 | 省略 `--output` 使用新的默认批次，或指定尚不存在的目录 |
| `check` 提示交付文件变化或集合不同 | 核查本地修改及缺失文件；`check` 要求交付文件保持与 `MANIFEST.sha256` 一致，`.git/`、`.tools/`、`runs/` 和 Python 缓存不纳入核验 |
| 构建或生成失败 | 查看本批次 `failure.json` 及对应 `*.stderr.log`、`*.status.json`；不要将失败批次当作通过结果 |
